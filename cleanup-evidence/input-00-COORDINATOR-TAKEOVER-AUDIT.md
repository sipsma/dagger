**What the Human was trying to finish.** The deliverable is engine functionality that lets another engine receive selected cached values and their dependencies, use them through ordinary cache lookup, and obtain filesystem content lazily. The cache service chooses what is worth exporting or supplying. The engine supplies the operations. Designing or implementing the actual remote cache service, its communication channel, or a synchronous remote request on every cache miss is outside this assignment.

A useful concrete example is a Container whose filesystem was produced by a lazy operation on engine A. Engine B should be able to import its cached value and the original inputs without immediately downloading filesystem layers. When a caller needs that filesystem, B can use an available local snapshot, otherwise try the supplied snapshot chain, and, if that download is unavailable or fails, run the original lazy producer. If A never evaluated the producer, B still needs the same producer inputs; it simply has no completed output to download. Completed and pending exported results both matter. A metadata-only hit must remain metadata-only.

This is an extension of existing lazy evaluation, persistence, and snapshot transfer. It is not a new consistency architecture. A function result does not become invalid merely because a File it once read is later pruned. The Human explicitly accepted ordinary nondeterminism, including using `/out` from one execution and computing stdout later from another. Missing an optimization is acceptable; teaching an incorrect equality is not. Remote metadata must not silently transport unsafe content equalities through an indirect alias mechanism.
