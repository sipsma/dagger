## Representation and behavior

1. Directory, File and Container keep their Lazy operation after evaluation. `IsEvaluated` reads the whole-operation latch; refined Container groups continue to use `GroupConsumed`. Pending reporting, detached cloning, persistence, capture, routing and schema cloning use completion state rather than pointer absence. Directory/File completion validates installed output accessors and records the output revision once. Body completion and cache bookkeeping remain separate, so a failed sync retries bookkeeping without a second body. The [reader inventory](READER-INVENTORY.md) records every mechanically selected occurrence, including writes and tests.

2. Plain, stateful HTTP resolution still resolves or revalidates the origin. It releases its temporary returned ref on every exit and selects the persistable `__httpFile` call with URL, body digest, layout name, mode, optional checksum, Last-Modified and platform. Its File is pending. First use selects local HTTP state without resolving it, matches the exact body/checksum under the state mutex, and pins the canonical snapshot before unlocking. Derivation and cleanup happen outside that lock. A missing or advanced state uses the existing verified stateless GET. Digest mismatch cannot replace the recorded output or change state validators. Cancellation, pin and cleanup failures remain visible. The File has no HTTPState dependency. A matching offered chain bypasses both origin access and Lazy evaluation. Authenticated and service-bound HTTP keep their existing session-scoped eager path.

3. Schema generation still computes deterministic bytes at selection, retaining the schema/view/argument identity and recording the default platform input. A fresh `FileBlobLazy` carries those bytes; scratch allocation and writing happen on use. Its temporary scratch ref is released inside the evaluated body. Returning an unused schema handle therefore no longer performs snapshot I/O, and snapshot failures surface later.

4. Mutable Git references and legacy commit-to-Ref selection resolve as before, then select persistable `__resolvedRef(name, commit)`. Fixed-SHA paths stay fixed. Tree, commit-tree and bundle handles contain fresh operations and do not materialize output until used. Saved tree operations use the recorded SHA; they never resolve the current branch. The public `withBundle` immediately consumes its internal Directory, so it can still force that work before returning. Cleaning still returns the original Directory when no worktree exists, without marking an unfilled output shell complete.

5. Empty Directory, both Container mounts and builtin Container are Lazy on every path. Scratch construction allocates no snapshot. Mount constructors settle metadata, copy plain metadata and mount shape, and allocate fresh output accessors; they do not clone rootFS, execMeta or mount refs during construction. Write groups release an uninstalled detached source on failure. Builtin construction validates the digest and defers whole-image work. Metadata consumers now demand metadata before expansion, platform/owner/config reads or mount lookup. This includes direct Directory/File selection and both legacy service branches. Work and errors move to first demand; the required cold SDK chain still demands builtin metadata immediately through its following mount, so no builtin I/O saving is claimed for that workflow.

6. Completed-value side fields and recording APIs are removed. Operation attachment and encoding use the retained Lazy operation or saved operation bytes. Private per-part acquisition reads operation data from the persisted row and creates a fresh operation; it does not reuse a consumed latch. The private release-observing ref decorator remains confined to that invocation's FS handle. Delegation, source ranking, independent pin ownership, publication receipts, OwnerSyncReady, scoped inline output ownership and D2 settlement retain their B4 contracts.

7. Acquisition APIs, fixture events and counters use Lazy operation names. Persisted foreign payloads carry strict `operationState` values `none`, `pending` or `evaluated`. Format versions are native schema **21**, envelope **5** and transfer bundle **2**. Old native stores take the existing schema-mismatch cold-start path; old transfer bundles/envelopes are rejected. The compatibility tests explicitly exercise the cut. These are intentional format and call-identity changes.

## Ownership-read failure and Decision 1

The earlier combined run returned `persist state not ready` in six HTTP methods during shared Container setup, and Git ended with fetch cancellation and a package timeout. The requested single-method isolation passed before the correction (HTTP permissions, 4.31 seconds), so a retained completed operation was not invariably rejected. Source inspection identified that ownership synchronization used the same try-lock reader as capture and publication. Another reader or encoder could hold that guard without an active operation body; the synchronizer propagated its transient refusal to callers. The exact first failing guard branch was not retained in the original bare error. The lock sequence and final correction have deterministic race coverage.

Coordinator Decision 1 at `bdfc380e66a0194ed26e052508802371379a6efe`, record blob `21683b4c447401c0d4d33057879459a00888f3dd`, authorizes a separate blocking ownership read. Container takes `lazyOpMu` and `LazyMu` in that order with ordinary locks. Completed groups are skipped. If a group body is running, the reader releases every pointer/state/group hold before waiting on that group's existing latch, then reads again. File/Directory release their output mutex before waiting on a pending body latch and skip evaluated bodies. There is no timer, sleep or scheduling-poll retry. The revision is advanced before body completion becomes visible.

The Container encoder now captures its operation pointer before taking the state latch. This removes the reverse acquisition of the pointer latch while holding state, which would deadlock a blocking ownership reader waiting for the encoder. This ordering correction preserves the nonblocking capture guard and shutdown behavior. Ownership synchronization alone selects the blocking typed read, including scoped inline values; capture, Commit, boot and import retain the nonblocking path. Revision validation still detects a changed output, and real read/lease failures keep the existing bookkeeping retry semantics. Ordinary calls now wait for legitimate reader/encoder/body contention instead of failing with a guard-busy error.

The final race checks pass for completed Container/File reader contention, active Container-group/File-body contention, encoder contention, fresh publication, explicit owner sync, inline scoping and the affected shutdown case. They verify that a waiting reader releases the latches needed by the body to finish. Their commands and logs are in [the ledger](COMMANDS.md). All eighteen requested engine methods passed on this final locking implementation. The earlier timer-based run and removed test remain explicitly historical. Previously accepted package, cold, warm, mixed, restart and default-policy selections stand under the coordinator's no-repeat direction; they were not rerun after this focused correction.
